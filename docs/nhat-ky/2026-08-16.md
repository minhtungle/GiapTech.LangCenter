## Quyết định

| Quyết định | Loại bỏ phương án | Vì sao |
|---|---|---|
| **Denormalize `tenant_id` xuống 7 bảng con** | Join lên bảng cha | Filter chỉ áp cho entity có `TenantId`; thiếu nó thì mọi truy vấn trực tiếp phải nhớ join, quên một lần là rò rỉ chéo CLB. Thừa một cột `uuid` rẻ hơn rủi ro đó |
| **Chỉ mượn `PasswordHasher` của Identity** | Kéo cả Identity stack | Identity giả định username duy nhất **toàn cục**, trái thẳng với multi-tenant nơi hai CLB đều có `admin` |
| **Mã đội 7 ký tự sinh tự động** | Người dùng tự đặt ID | Tên dạng "FC ..." rất dễ trùng giữa CLB phong trào |
| **Bộ 31 ký tự, bỏ `0/O` và `1/I/L`** | Đủ 36 ký tự | Người dùng đọc mã qua điện thoại, chép tay — nhầm 0 với O là lỗi hay gặp. Vẫn còn 31⁷ ≈ 27 tỷ tổ hợp |
| **Chặn buộc-đổi-mật-khẩu ở tầng API** | Chỉ trả cờ cho frontend | Token vẫn hợp lệ; ai biết `admin/123456` là gọi thẳng API dùng được ngay |
| **Policy phân quyền sinh động** | Đăng ký sẵn từng tổ hợp | Số tổ hợp = số chức năng × 4 và tăng theo mỗi module; danh sách tay sẽ thành thứ phải nhớ cập nhật |

**Nới luật phụ thuộc:** test tôi viết ban đầu cấm `Application` dùng EF Core, nhưng `IAppDbContext`
với `DbSet<T>` là mẫu chuẩn Clean Architecture. Luật quá chặt, không phải code sai — sửa luật thành
cấm **provider** (`Npgsql`), giữ `Domain` nghiêm ngặt như cũ.

> ⚠️ Việc không dùng Identity đầy đủ **lệch nhẹ** so với `CLAUDE.md` mục 4 ("ASP.NET Core Identity +
> JWT"). Hiện mới ghi trong commit message — **nên viết ADR-0005** cho đúng quy tắc #6.

## Vướng mắc & phát hiện

### Lỗi rò rỉ dữ liệu chéo tenant — nghiêm trọng nhất

Bản đầu dựng query filter bằng `Expression.Constant(currentTenant)` — trỏ ra object ngoài
`DbContext`. EF cache model dùng chung, nên object bị "nướng cứng" vào context đầu tiên:
**context của tenant B đọc tenant của A và thấy dữ liệu của A**. Không exception, không log, chỉ trả
về dữ liệu sai.

`CachLyTenantTests` bắt được. Sửa bằng `Expression.Constant(this)`. Đã kiểm chứng **hai chiều**:
đổi về bản cũ thì 2 test đỏ, đổi lại thì xanh. Ghi vào
[multi-tenant.md](../backend/multi-tenant.md#-bẫy-filter-không-được-trỏ-ra-object-bên-ngoài-dbcontext).

Trên đường sửa có viết thêm `TenantModelCacheKeyFactory`, nhưng phản chứng cho thấy nó **không phải**
nguyên nhân → gỡ bỏ, giữ giải pháp tối giản.

### Enum trả về dạng số — lọt qua toàn bộ 44 test backend

API nhận `HanhDong` là `0,1,2,3` chứ không nhận `"Xem","Them"`, nghĩa là màn Phân quyền **hỏng ngay
khi bấm Lưu**. Chỉ phát hiện khi tạo dữ liệu mẫu để người dùng kiểm tra thủ công.

Lọt lưới vì test tích hợp gửi JSON tay cho `/tai-khoan` và `/cau-thu`, không có test nào POST
`/quyen` với ma trận đầy đủ. **Đây là lý do chạy thật vẫn cần thiết dù test xanh.**

### `TreatWarningsAsErrors` là lớp phòng vệ ngoài dự kiến

Hai lần thử phản chứng bằng `if (false)` bị chặn ngay ở bước build (unreachable code) — phải xóa hẳn
thân nhánh mới chạy được test. Cờ này bắt lỗi sớm hơn dự tính.

### Ba thứ suýt hỏng khi chạy Docker

- **`UseHttpsRedirection` trong container**: sau Caddy thì TLS đã kết thúc ở proxy, bật redirect
  sẽ đá cả healthcheck lẫn request thật sang cổng HTTPS mà container không nghe. Thêm cờ
  `SAU_REVERSE_PROXY`.
- **`MigrateAsync` với provider in-memory**: integration test không có khái niệm migration →
  phải kiểm `IsRelational()` trước.
- **Cổng 9000 bị Docker Desktop chiếm** → MinIO không start. Dịch sang 59000 ở file dev.

### Lỗi hạ tầng test

- Seed gọi `BuildServiceProvider()` trong `ConfigureServices` → tạo container thứ hai, dữ liệu seed
  đi vào provider khác với provider ứng dụng đọc. Mọi test đăng nhập thất bại với triệu chứng trông
  y hệt lỗi logic.
- Nhiều test cùng đổi mật khẩu `admin` của một CLB → phụ thuộc thứ tự chạy. Thêm tài khoản `manager`
  không bị buộc đổi mật khẩu cho các test nghiệp vụ.
- Test đọc `factory.MaDoiA` **trước** khi gọi `CreateClient()` nhận chuỗi rỗng vì host chưa seed.

### Đã đóng khoảng trống PostgreSQL

Suốt 5 commit đầu mọi test chạy in-memory, tôi vẫn phải nói "chưa xác nhận trên DB thật". Hôm nay bật
được Docker và kiểm chứng:

- Migration áp sạch → 17 bảng, `jsonb` đúng kiểu
- **UNIQUE vote MVP chặn thật**: chèn trùng `(tran_dau_id, nguoi_vote_id)` bằng SQL trực tiếp bị DB
  từ chối. Trước đó chỉ chứng minh được nó *có trong script*, giờ chứng minh được nó *có tác dụng*
- Hai CLB **cùng tên** "FC Sông Hàn" nhận hai mã khác nhau — đúng vấn đề cần giải
- Đăng nhập bằng chữ hoa / chữ thường / có khoảng trắng thừa đều thành công

Cũng phát hiện `DesignTimeDbContextFactory` hard-code connection string nên
`dotnet ef database update` không trỏ được vào DB thật.
