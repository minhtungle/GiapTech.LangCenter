# 05/09/2026 — Tách base cho dự án LMS

Chuyển repo từ **quản lý CLB đá bóng** (`GiapTech.SoccerRoom`) thành **base cho hệ thống quản
lý trung tâm ngoại ngữ** (`GiapTech.LangCenter.LMS`). Bản bóng đá đầy đủ vẫn ở repo cũ.

## Quyết định đã chốt trước khi làm

| Hạng mục | Chọn | Vì sao |
|---|---|---|
| Multi-tenant | **Giữ** | Là giá trị lớn nhất của base này; bỏ đi thì mất luôn lý do dùng lại |
| Từ ngữ định danh | Đổi cả code lẫn UI → `MaTrungTam`/`TenTrungTam` | Base mới chưa có token lưu hành nên đổi claim JWT không tốn đường lui |
| Migration | Xoá 14 migration cũ, tạo lại 1 `InitialCreate` | DB mới hoàn toàn, không phải migrate dữ liệu → không vướng quy tắc #1 |
| Tenant fields | Giữ nhóm liên hệ + ngân hàng/QR | Trung tâm cũng thu học phí, cần chỗ hiện số tài khoản |
| Bộ test | **Re-point**, không xoá | Test bảo mật đều dùng `/api/v1/cau-thu` làm endpoint thử — xoá là mất lưới an toàn đã trả giá để có |

## Thứ tự làm: xoá nghiệp vụ TRƯỚC, đổi tên SAU

Không phải tuỳ ý. 14 migration cũ (mỗi `.Designer.cs` chứa 65–101 lượt `SoccerRoom`) biến mất
cùng bước xoá, nên khối lượng thay chuỗi ở bước sau giảm rất nhiều.

## Bốn lỗi tìm ra, đáng ghi lại

### 1. Endpoint đọc ảnh gác bằng quyền của module bị xoá

`AnhController.Doc` — endpoint đọc **mọi** loại ảnh — đang gác bằng
`[RequirePermission(ChucNang.CauThu, Xem)]`. Bỏ `CauThu` khỏi danh mục quyền mà không đổi chỗ
này thì **mọi ảnh kể cả logo trả 403**, âm thầm, và **không test nào bắt được**.

→ Thêm `ChucNang.Anh` riêng. Bài học chung: **quyền của một endpoint dùng chung không được vay
quyền của một module cụ thể** — module đó biến mất là endpoint chết theo.

### 2. Quy tắc #1 bị vi phạm ngay trong handler thiết lập

`CapNhatThietLapHandler` có hai quy ước trái ngược:

```csharp
t.MoTa = request.MoTa;                    // null từ client → XOÁ dữ liệu
if (request.DiaChi is { } dc) ...         // null từ client → giữ nguyên
```

Bốn trường `TenVietTat`/`MoTa`/`LogoUrl`/`AnhBiaUrl` theo cách một, sáu trường còn lại theo
cách hai. An toàn ở dự án cũ **chỉ vì form luôn gửi đủ** — an toàn nhờ may, không nhờ thiết kế.

Phát hiện khi kiểm tay trên PostgreSQL thật (gửi `PUT` chỉ có `tenTrungTam`, đọc lại thấy mất
`moTa` và `tenVietTat`). Đã đưa về một quy ước, thêm 2 test vào
`CapNhatKhongMatDuLieuTests` và **kiểm bằng phản chứng** — hoàn nguyên code thì test đỏ đúng.

### 3. Route BE và FE đã lệch mà test vẫn xanh

Backend giữ route `auth/ten-doi/{ma}` (chuỗi route không bị bước đổi định danh chạm tới), còn
frontend đã gọi `auth/ten-trung-tam/{ma}`. **Test cũng dùng tên cũ nên vẫn xanh** — lỗi tích
hợp mà test backend không thể bắt.

→ Sau khi sửa, soát **toàn bộ** endpoint FE gọi so với `swagger.json` bằng script thay vì sửa
từng chỗ khi gặp. Kết quả: không còn chỗ lệch nào khác.

### 4. CI và compose vốn đã kéo hai image khác nhau

Repo có **4 lược đặt tên lẫn lộn từ trước**: `GiapTech.SoccerRoom` (code), `soccercity`
(compose project + image), `soccerroom` (JWT issuer · MinIO bucket · SMTP), `clubmgmt` (DB name
trong `.env.example`). CI push `ghcr.io/$owner/soccerroom-api` còn compose kéo
`ghcr.io/minhtungle/soccercity-api` — hai bên **đã không khớp trước lần này**. Nay về một tên
`langcenter-lms`.

## Test: re-point thay vì xoá

Các test bảo mật giá trị nhất đều dùng `/api/v1/cau-thu` làm endpoint thử và `CauThu` làm
entity mẫu. Xoá là mất lưới an toàn, nên chuyển sang `/api/v1/tai-khoan` và `Quyen`:

| Test | Canh gì | Xử lý |
|---|---|---|
| `PhanQuyenVaCachLyTests` | JWT giả, thiếu quyền, buộc đổi mật khẩu, cách ly tenant | đổi endpoint thử |
| `CachLyTenantTests` | Query Filter cả hai chiều | đổi entity mẫu → `Quyen` |
| `PhanTrangTests` | phân trang, bộ lọc áp **trước** khi cắt trang | viết lại trên `/tai-khoan` |
| `DongThoiTests` | ràng buộc "chỉ một" ở tầng DB | viết lại trên 7 UNIQUE hệ thống |

`DongThoiTests` còn được **thêm hai test chiều ngược** mà bản gốc chưa có: `UNIQUE(username)`
phải gồm `tenant_id`, và cùng một username tạo được ở hai tenant. Không có chúng thì ai đó
"sửa" lỗi trùng username bằng cách bỏ `tenant_id` khỏi UNIQUE mà bộ test vẫn xanh.

## Kiểm chứng

- 128 test backend xanh (35 unit + 93 integration), build 0 warning.
- Frontend `tsc -b` + `vite build` sạch; i18n 814 → 207 dòng.
- **PostgreSQL thật**: migration áp sạch, đúng 7 bảng,
  `ix_nguoi_dung_tenant_id_username` gồm `tenant_id`.
- **Đầu-cuối**: tạo trung tâm → mã 7 ký tự → đăng nhập → bị chặn `PHAI_DOI_MAT_KHAU` (403) →
  đổi → vào hệ thống → danh mục quyền đúng 5 chức năng → lưu thiết lập → gửi `PUT` thiếu
  trường, không mất dữ liệu → tải logo lên MinIO, đọc lại 200 → tenant 2 đọc ảnh tenant 1
  trả 404.
